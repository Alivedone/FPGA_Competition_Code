# LSS_HSR目标识别 · 局部轨迹详情版

## 启动与使用

1. 板卡沿用r04硬件服务，默认TCP5001；PC设置可达网络。GUI不配置板卡网口、不通过SSH启动服务。
2. 安装带Tk的Python 3.10+，双击启动上位机.cmd。启动器会选择可用Python，错误记录在output/startup.log。
3. 连接并读取模型，添加dataset/new_data下的BIN，必须保留同名JSON。起始帧从0开始，当前每个文件固定推理一个连续10帧窗口，要求起始帧+10不超过文件总帧数。
4. 选择PC结果目录，按列表发送。同一文件可以重复添加；任务完成并收到服务READY后再发下一项。断开仅关闭连接，STOP会完成当前任务后停止板端服务。
5. 任务结果列表选中一项，点击“查看识别详情”或双击。详情只显示该10帧的局部轨迹图；左上角为预测类别图片。已移除频谱瀑布图和概率柱状图，底部保留预测类别、最高概率及校验说明。

## 组合BIN与板卡兼容

new_data每帧包含512点已标准化频谱和5维原始轨迹，FP32小端、2068字节。客户端核对同名JSON格式、列顺序、单位、预处理参数和BIN SHA256，按帧拆出频谱和轨迹，不重新标准化。

线上仍发送完整文件中拆出的纯频谱：每帧2048字节、模型窗口20480字节。START/DATA长度及CRC都按这份实际上传频谱计算。轨迹不送入NPU，只在PC用于对应窗口显示；板端协议、模型和PL无需修改或重新编译。

服务默认64MiB上限按实际上传的纯频谱计算。预览帧数按实际源格式计算，不把轨迹20字节误算成频谱。旧dataset/data_stand纯512点BIN仍支持推理，但没有轨迹；界面明确提示，不按同名文件猜测配对。

## 文件与轨迹如何关联

同一组合BIN里的第i帧，512点频谱与后5个轨迹值天然对应。用户选择起始帧s后，推理和轨迹均使用s～s+9帧。

每个PC task_*目录保存：

- task.json：网络START元数据、原路径、原组合BIN SHA256和字节数、源格式。file_bytes/crc32指实际上传频谱；original_file_bytes/original_sha256指原组合BIN。
- model_info.json、events.jsonl、client_report.json、windows.tsv、w10_sN.output.bin：模型描述和结果证据。
- w10_sN.input.bin及.input.json：实际上传的10×512频谱快照及校验。
- w10_sN.track.bin及.track.json：同一窗口的10×5轨迹快照，固定200字节。JSON绑定任务ID、起始帧、输入窗口CRC、上传频谱整文件CRC、原组合BIN SHA256、轨迹CRC及列定义。

查看详情前校验输出和输入/轨迹关联。原文件移动后仍可看已归档窗口；快照损坏或错配时清空轨迹并显示错误，不沿用上一任务轨迹。旧历史结果无轨迹快照时提示不可用，重新用组合BIN发送可生成新档案。

局部轨迹采用X=R*sin(方位角)、Y=R*cos(方位角)，从所选窗口第一个点扣除原点后以米显示；自动适应当前10帧范围，保持X/Y等比例。绿色起点、红色最新点，箭头和点旁帧号表示运动顺序。不显示雷达同心圆，不代表已经标定的东西南北或校正斜距后的水平位置。

## 后续补充类别图片

图片目录：assets/class_images。默认模型数字标签0～8分别对应class_0.png～class_8.png；可修改class_images.json中“模型标签→图片文件名”的映射。不要根据数据文件夹名称猜测训练编号，待正式class_to_idx确认后再对应图片。

支持PNG/GIF，文件名必须为同目录文件，不允许跨目录路径；图片自动等比缩小显示。缺图时显示“类别X的图片待补充”，不会用别的类别图片顶替。补图后重新点击详情即可加载。

图片是类别参考图，不是本次输入拍摄的现场图片；网络误判时也会按实际预测标签展示，不按文件夹真值覆盖预测。

## 换电脑与验证范围

复制整个scriptsv2（包括assets目录和配置）及组合BIN/JSON即可；PC无须安装Icraft、MATLAB、numpy或scipy。原启动器保留。

本次使用真实Tk和本机C++合成分类测试后端，九个对象组合BIN及旧512点BIN完成14任务测试，验证按帧解包、起始帧2、10帧轨迹关联、A/B/A、缺图占位和PNG加载、轨迹损坏/错配拒绝、原文件缺失后离线显示及STOP。该测试不代表本次NPU实板执行或真实标签准确率。协议及摘要校验通过不等于分类正确。

## 已配置图片与离线测试数据

已从dataset/data_set_pic原样复制九张PNG至assets/class_images，未改变源图片。标签顺序依据dataset.py：0 UAV1、1 UAV2、2 UAV3、3 UAV4、4 Bird、5 Birds、6 Wing Bird、7 Rotate、8 Car；实际训练模型需沿用该标签顺序。

无需连接板卡，在主界面点击“加载离线示例”，结果表中会加入18项，选择一项后点击“查看识别详情”：

- examples/real_cpu：9份既有真实PC Icraft HostBackend ResNet输出，与new_data相应首窗输入逐字节核对。界面标为“离线PC真实结果”；不是NPU实板结果，不能据此证明训练标签准确率。
- examples/image_demo：9个人为指定标签0～8的显示样例，覆盖所有类别图片；输入轨迹是真实记录，但分类输出是为检查图片映射构造的。界面标为“图片映射演示”，不得当作模型预测。

也可点击“加载历史任务”选择某个examples子目录内的task_*文件夹。快照已包含，无需原始数据路径；不要将这些结果目录当作可直接上传的BIN集合。examples/index.json记录全部任务及其来源。

## 放大轨迹与刻度间隔

默认自动放大当前10帧局部运动，X/Y均显示相对窗口起点的投影位移（m），不会把远处目标与雷达原点一起缩在大圆内。左上角类别图片保留，绘图区预留图片侧栏，不遮挡轨迹。

在详情窗口填写“X刻度间隔/m”和“Y刻度间隔/m”，点击“应用间隔”或回车；例如填10表示每10米一个网格，0表示自动。改变刻度不会改变点的位置、采样帧或推理输入。间隔过小导致超过60个刻度时提示增大间隔，避免图面过密；点击“自动适应”恢复自动刻度。

所有观测点原样连线，保留10点及帧号；静止目标的重复位置会重合，不人为拉开点距或插值制造运动。
