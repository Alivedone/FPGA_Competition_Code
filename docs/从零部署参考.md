# LSS HSRV3：全新电脑与新板卡从零配置操作步骤

完整顺序：准备材料→配置新PC→恢复系统SD卡并部署本项目BOOT→新板首次启动→网络/SSH→SDK和构建环境→上传项目→创建/启用swap→板端编译→启动ResNet18→PC收发与UART验收。

**本流程适用于与本项目BOOT/PL匹配的开发板、DDR和BSP。** 任意ARM64板卡不能直接使用这套BOOT/PL；更换板型或DDR配置时，需先取得对应的系统和硬件适配文件。本文复现程序部署和运行，不包括重新训练模型。

## 2. 新Windows电脑安装与工程准备

1. 安装板卡控制台所用USB转串口/调试器驱动，插入后在设备管理器确认实际COM号。
2. 安装终端工具，例如MobaXterm，用于串口控制台、SSH和SFTP。
3. 安装Python3.10或更新版本，安装时包含Tcl/Tk。PC上位机只使用标准库，不需安装numpy、scipy、MATLAB或Icraft。
4. 完整复制prj_git_final到`C:\LSS_HSRV3\prj_git_final`，保留assets/examples等相对目录，选用可写位置。
5. 准备有线网卡、网线；准备配套系统镜像、SDK包以及正式测试BIN/JSON。

完整复制工程目录，保留RAW/EDIF等模型和硬件文件的实际内容、文件字节及换行。仅运行上位机不要求安装Vivado或板端SDK。

在PC PowerShell执行启动自检：

```powershell
Set-Location -LiteralPath 'C:\LSS_HSRV3\prj_git_final\上位机'
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\start_gui.ps1 -SelfTest
```

应显示GUI_STARTUP_SELF_TEST_PASS。双击启动上位机.cmd，可先加载离线示例检查图片/轨迹。错误记录在上位机/output/startup.log。离线示例不调用板卡，不代表新板或当前ResNet18推理已验证；真实联调后续执行。

## 3. 新SD卡：恢复完整系统，再放入项目启动组件

### 3.1 使用完整镜像恢复SD卡

板卡断电，取出目标SD卡并插到新PC读卡器。写镜像会覆盖目标卡的分区和数据，先确认读卡器对应的容量/盘号并保留需保存的数据。

使用配套imageUSB工具，选择正确SD设备、写入已有镜像的功能，以及第1节的`icraft_v3_ubuntu20.04_aarch64_sd_image.bin`，按工具流程写入并校验。这里不是把31.9GB的bin作为普通文件复制到FAT分区，也不是给SD卡简单格式化成一个FAT32分区。

若使用其他厂商提供的正式系统镜像，按其说明恢复完整启动分区和Linux根分区；后续必须满足本项目的ARM64/BSP、驱动、DDR及启动配置要求。不要用通用Ubuntu镜像替代板卡专用BSP。

### 3.2 确认系统需要的两个分区

项目当前uEnv.txt配置为：

```text
root=/dev/mmcblk0p2
从mmc 0:1加载Image和fmqlmp-verify.dtb
```

因此通常需要：第一分区为启动FAT分区，第二分区为EXT4 Linux根文件系统。Windows常只显示第一个FAT分区；看不到第二分区盘符不代表它不存在。不要因为Windows不识别EXT4而将其格式化。

### 3.3 放入本项目的启动文件

完整系统恢复成功后，打开SD卡的FAT启动分区，先备份其中同名文件，再将新电脑`prj_git_final/sd/`中的以下四个文件复制到该分区根目录：

```text
BOOT.bin
Image
fmqlmp-verify.dtb
uEnv.txt
```

这些文件需作为匹配的一组使用。不要仅使用镜像里默认演示工程的BOOT就假定已经具有本项目LSV2/LSC2桥接硬件。当前BOOT包含兼容的PL配置；单独的.bit不需要再作为Linux应用运行，也不通过把PS可执行文件放进BOOT来更新应用。

不必把sd/中的FSBL、BL31、U-Boot或多个候选bit文件全部复制为新的启动入口；当前运行的FSBL/PL/后续引导载荷已封装在对应BOOT中。更换这些组件需单独验证，不在首次运行时自行重组。

本次配套BOOT的SHA256为：

```text
668c5fb3c2afda094084968bcc03f628e282acc2a1c1e6d01e905509f9af67ca
```

安全弹出SD卡，装回兼容新板，将启动模式按该板手册设置为SD启动。镜像版本不同时，还需核对其根分区编号与项目uEnv一致；本项目文件没有提供任意BSP组合的兼容保证。

## 4. 新板首次上电与控制台确认

连接电源和板卡调试串口。PC终端选择新出现的实际COM号，115200、8数据位、无校验、1停止位、无流控。上电观察BootROM/引导、PL、Linux启动日志；不能只看到U-Boot提示符就认为Linux环境已完成。

按镜像/板卡提供方给出的账户密码登录，不预设通用默认密码。后续/root目录、软件包安装和swap命令要求root权限。Ubuntu系统如以普通用户登录，可在授权允许时进入root终端：

```bash
sudo -i
```

首次确认：

```bash
id
uname -a
uname -m
cat /etc/os-release
lsblk -f
findmnt /
df -h /root
free -h
```

检查点：架构aarch64；系统为匹配的Ubuntu/BSP；根分区正常挂载且可写；/root有足够空间；内存符合板卡配置。使用Ubuntu20.04 AArch64配套系统，具体可见内存以板卡配置和镜像为准。

若提示找不到/dev/mmcblk0p2或无法挂载根文件系统，先修正SD镜像/分区/uEnv匹配；若PL初始化/DDR异常，先检查板型、BOOT和硬件配置。不要跳过这些问题直接进行C++编译。

## 5. 新电脑和新板网络、SSH首次配置

### 5.1 临时直连IP

PC有线网卡设为192.168.1.22、掩码255.255.255.0；直连测试可不设网关/DNS。先确认网卡真实名称和地址无冲突，不修改无关Wi-Fi/VPN。

在板卡串口查看网口。以下以eth0为例，实际名称不同时替换后再执行：

```bash
ip -br link
ip link set dev eth0 up
ip -4 addr show dev eth0 | grep -q 'inet 192.168.1.11/24' || ip addr add 192.168.1.11/24 dev eth0
ip -4 -br addr show dev eth0
cat /sys/class/net/eth0/carrier
```

应看到192.168.1.11/24与carrier=1。这是临时配置，重启后重新确认；此配置不等于板卡已经能访问互联网。需要在线装包时，另按实际路由器/网络配置有效网关和DNS，不把PC地址直接当网关。

PC PowerShell检查：

```powershell
ping 192.168.1.11
```

### 5.2 SSH/SFTP服务与认证

板端检查SSH是否安装并监听：

```bash
command -v sshd
ss -lntp | grep ':22 '
```

Ubuntu镜像已装OpenSSH但未运行时，使用：

```bash
systemctl enable --now ssh
systemctl status ssh --no-pager
```

如果镜像未安装SSH，按第6节在可用的软件源或配套离线环境中安装openssh-server，再启动服务。若BSP不使用systemd，则采用其对应启动方式。登录账户与root访问策略按镜像实际配置处理，不通过关闭认证绕过登录问题。

用MobaXterm新建SSH/SFTP会话，地址192.168.1.11、端口22，使用新板实际账号/认证方式。首次连接应通过板端串口核对主机公钥指纹，例如：

```bash
ls /etc/ssh/ssh_host_*_key.pub
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

如客户端显示另一种算法，核对对应公钥。可使用板卡允许的密码认证上传；如需免密登录，在本电脑生成SSH密钥，并将公钥安装到板卡对应账户。

PC也可以安装Windows“OpenSSH客户端”可选功能后检查22端口：

```powershell
Test-NetConnection -ComputerName 192.168.1.11 -Port 22
```

仅TCP上位机业务不使用SSH密码；SSH/SFTP主要用于这次部署、维护和下载日志。

## 8. 编译之前创建或启用swap

在编译前配置swap。确认推理服务已停止，在板卡root终端整段执行以下命令：缺少文件时创建1GiB，已有文件时只启用，不重新格式化。

```bash
bash <<'SWAP_PREPARE'
set -e
swap_file=/root/lss_v3_build.swap
if [ ! -e "$swap_file" ] && [ ! -L "$swap_file" ]; then
    available_kb=$(df -Pk /root | awk 'NR==2 {print $4}')
    test "$available_kb" -ge 1572864 || {
        echo 'STOP：/root可用空间不足1.5GiB，请先检查磁盘并为编译输出留足空间。'
        exit 1
    }
    umask 077
    dd if=/dev/zero of="$swap_file" bs=1M count=1024 conv=excl status=progress
    chmod 600 "$swap_file"
    mkswap "$swap_file"
else
    test -f "$swap_file" && test ! -L "$swap_file" || {
        echo 'STOP：目标不是普通文件，请检查，禁止覆盖。'
        exit 1
    }
fi
if ! swapon --noheadings --show=NAME | grep -Fxq "$swap_file"; then
    swapon "$swap_file"
fi
test "$(awk '/^SwapTotal:/ {print $2}' /proc/meminfo)" -gt 0
swapon --show
free -h
echo SWAP_READY
SWAP_PREPARE
```

必须看到SWAP_READY且Swap总量大于0后才编译；USED为0正常。如果swapon为空、Swap总量为0B，表示没有启用。已有文件若启用失败，先检查报错和文件身份，不直接重复mkswap，也不覆盖或删除活动swap。

本步骤不写fstab，重启后需再次运行检查/启用；编译保持单线程，不在编译期间swapoff。若新系统不支持swap文件，应先按系统要求配置可用swap后再继续。

## 9. 在板卡单线程编译PS程序

确认第8节swap已就绪，在板卡执行：

```bash
cd /root/prj_git_final/ps_code/lss_hsrv3_timing
bash build_on_board.sh
```

脚本会完成：

1. 核对aarch64与源码SHA256。
2. 创建libdl/libdw兼容链接，查找已有Icraft CMake包。
3. 在独立`build_ps/`中以-j1编译正式程序。
4. 主程序/NPU封装保持-O0，仅CPU专用`ps_hotpath.cpp`使用-O2，禁用该单元的fast-math/LTO并检查实际编译参数。
5. 检查动态库依赖，生成`PS_BUILD_SHA256SUMS`构建凭据。

成功时最后显示：

```text
PS_UPGRADE_BUILD_PASS board_inference_not_tested
```

确认产物与依赖：

```bash
ls -lh build_ps/lss_v3_timing
file build_ps/lss_v3_timing
ldd build_ps/lss_v3_timing
sha256sum -c PS_BUILD_SHA256SUMS
```

`file`存在时应显示ARM64/AArch64 ELF；ldd不应出现not found。若出现Killed、SDK/CMake包缺失、库缺失或校验失败，先处理问题，不继续启动。不要通过关闭源码校验掩盖文件混用。

**本目录未提供CTest测试目标。** 编译成功表示构建、参数和依赖检查完成；真实推理与功能验收按第11节执行。

编译完成、确认空闲内存允许后，在启动推理前关闭本次编译用swap：

```bash
swapoff /root/lss_v3_build.swap
free -h
```

若swapoff失败，保留文件并检查内存，勿删除活动swap。文件可以保留，下次编译按第8节重新启用；日常运行不需要重新创建它。

## 11. 新PC进行真实发送、接收和停止验证

1. 启动板端第10节选定的服务，再双击PC的`上位机/启动上位机.cmd`。
2. 连接`192.168.1.11:5001`，超时可设120秒；读取模型信息，确认model_id为resnet18_sjp，输入为`[1,10,512,1]`，对应9类输出/36字节。
3. 选择另行准备的已标准化FP32 BIN。默认起始帧0、窗口数1、步长1，文件至少有10帧；不要对已标准化数据再次标准化。
4. 点击按列表发送并接收，检查每任务的RESULT、DONE及下一次READY，结果保存至PC上位机output。
5. 使用相同文件重复，再按A/B/A输入验证结果一致性；有UART时检查主页、history/detail及同一条记录的对应关系。
6. 结束时选择“当前任务完成后停止服务”，等待STOPPED及板端TIMING_SERVICE_EXIT=0。仅断开连接不会停止板端程序，不强制结束正在操作硬件的服务。

输入支持512点纯频谱，以及带对应格式JSON的517点频谱＋轨迹组合文件。组合输入每帧取512点频谱上传，5个轨迹值仅在PC显示，不能把整帧517点直接当NPU输入。正式测试数据应另行复制；examples目录提供离线显示示例及快照，正式输入BIN与对应JSON需单独准备。

ResNet18配置写明`preprocessing=none`，表示板端不再标准化，PC提供已经按训练约定处理过的数据；归一化与类别顺序以config/resnet18_sjp.json为准。当前类别顺序为UAV1、UAV2、UAV3、UAV4、Bird、Birds、Wing Bird、Rotate、Car。传输校验通过不等于真实类别正确，应另有标签和统计流程评价准确率。

首次复现建议记录模型/二进制/输入身份、原始输出、任务数量和完整日志。在当前平台完成真实输入、重复运行及正常停止验证；准确率和长期稳定性应使用对应数据集与测试时长另行评估。

## 13. UART历史查询、备份与重置

历史文件是`/root/prj_git_final/ps_code/lss_hsrv3_timing/runtime_evidence/hmi_history.jsonl`，不是console.log。程序运行且UART正常时，可以不连接PC，从history选择记录进入detail；当前程序仍需正常初始化模型/NPU。

首次启动时如无历史文件，程序会创建空历史；成功识别后将记录写入该文件，供屏幕history/detail查询。

需要重置当前目录的历史时，先正常STOP并确认服务退出，再执行：

```bash
bash <<'HISTORY_BACKUP'
set -e
cd /root/prj_git_final/ps_code/lss_hsrv3_timing
for process in lss_v3_timing lss_v3_baseline hmi_uart_demo; do
    if pgrep -x "$process" >/dev/null; then
        echo "STOP：程序仍在运行，请先正常停止：$process"
        exit 1
    fi
done
if [ -f runtime_evidence/hmi_history.jsonl ]; then
    backup_dir=$(mktemp -d runtime_evidence/history_backup_XXXXXX)
    mv -- runtime_evidence/hmi_history.jsonl "$backup_dir/"
    echo "历史已备份到：$PWD/$backup_dir/hmi_history.jsonl"
else
    echo "没有当前历史文件；下次启动会创建空历史。"
fi
HISTORY_BACKUP
```

按10.2重新启动后历史为空，下次成功识别从R0001编号。保留.lock文件，无需删除；不要删除整个runtime_evidence，避免丢失日志和备份。

## 15. 常见问题

| 现象 | 检查与处理 |
|---|---|
|新PC找不到Python或Tk|安装Python 3.10+并包含Tcl/Tk，重新运行启动自检，查看上位机/output/startup.log|
|离线图片或详情缺失|确认完整复制assets/examples；正式任务同时保留输入文件、格式JSON及结果快照|
|连接5001失败|确认板端服务已READY、IP/网线/网卡设置正确；网络可达后再排查防火墙，不关闭无关安全设置|
|Config missing|从ps_code/lss_hsrv3_timing启动并显式传../../config/resnet18_sjp.json，必须显式指定ResNet18配置|
|SDK/CMake包找不到|板卡需匹配Icraft环境，脚本查找/usr及/usr/cmake；按第6节和SDK安装说明配置，swap不能解决SDK缺失|
|Killed或编译内存不足|检查swap总量、空闲内存及其他编译进程，保持-j1，停止并行构建；不要在编译中swapoff|
|Missing libdw/libdl或ldd出现not found|补齐匹配运行库/开发库及加载环境，不能复制不兼容架构的PC库|
|SHA256校验失败|检查是否文件遗漏、文件不完整、文本换行被转换或版本混用；重新复制同一版本，勿直接删掉校验|
|PS build missing or stale|启动依赖PS_BUILD_SHA256SUMS，先在本目录重新运行构建脚本；不要只放二进制却遗漏其凭据和被校验源码|
|No tests were found|当前prj_git_final未提供CTest项目，此输出不能当作功能通过；按真实发送流程验证|
|HMI_CONNECTED但屏幕异常|核对实际设备、波特率、屏幕项目与控件，查看HMI_LINK_ERROR/HMI_FATAL；仅连接成功不足以证明真屏可用|
|屏幕没有历史记录|首次启动历史为空；先完成成功识别任务，确认第13节的历史文件已生成且UART正常|
|requires_restart=true或硬件FAULT|保存日志，停止新任务，按板卡/SDK文档的硬件恢复流程处理，不直接强杀/复用正在占用的硬件|
